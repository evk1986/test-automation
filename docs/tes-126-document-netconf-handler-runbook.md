# Runbook – Deploy NETCONF Handler (PRB‑4821)

## Overview
This runbook describes the steps to roll out the new NETCONF handler for the Device‑Probe service, verify its operation, adjust the DLQ visibility timeout, and perform a rollback if necessary.

## Deployment Steps
1. **Build and Publish**
   - Run `./mvnw clean package -DskipTests`.
   - Push the Docker image `registry.internal/netatlas-probe:netconf‑v2.0.0` to ECR.
2. **Update Kubernetes Deployment**
   - Edit `k8s/probe-deployment.yaml` to reference the new image tag.
   - Apply with `kubectl apply -f k8s/probe-deployment.yaml --context prod-use1`.
3. **Verify Pods**
   - `kubectl rollout status deployment/probe-service -n netatlas --context prod-use1`.
   - Ensure all pods are `Ready` and the health endpoint returns `UP`.
4. **Smoke Test**
   - Publish a test `NetconfJobMessage` to `probe.commands` via the AWS CLI.
   - Confirm processing via CloudWatch logs and Cassandra `probe_job` table.

## DLQ Visibility‑Timeout Reset
1. Navigate to the SQS console for `platform.results.dlq` (region `us-east-1`).
2. Select the target message and choose **Change visibility timeout**.
3. Set the timeout to **300 seconds** (5 minutes) to allow immediate re‑processing.
4. Document the change in the ticket PRB‑4821.

## Rollback Procedure
1. Re‑apply the previous Docker image tag (`netconf‑v1.5.3`).
2. Run `kubectl rollout undo deployment/probe-service -n netatlas --to-revision=2`.
3. Verify that the old handler processes new messages without errors.
4. Clear any DLQ messages that were generated by the failed deployment.
